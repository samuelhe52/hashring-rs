# Dashboard 运行列表减少清单读取

`manifest.json` 保存运行时的源码差异。在本机的 25 份运行记录中，清单合计 166.7 MiB。此前每次读取运行列表都会读取并解析全部清单，尽管列表只使用配置、启动时间和结果状态等字段。

实验启动时写出 `run-metadata.json`，它与完整清单共用同一个元数据结构。Dashboard 用小文件读取清单字段，继续从 `summary.json` 读取状态和用时。完整清单可从原文入口读取。对于仅有完整清单的结果，服务缓存展示字段并以文件属性判断是否需要重读。缓存按服务进程存活，重启后这类记录的首次读取仍要解析完整清单。

在同一台 Windows 机器上用 Node.js 24.9.0 直接调用 `listRuns()`，同一批 25 条结果的三次基线耗时为 644–768 ms。改动后首次读取原清单耗时 648 ms，随后五次耗时 40–61 ms。把同一批配置和结果复制到临时目录并写成轻量元数据后，五次新建结果存储的读取耗时为 45–50 ms。三组返回的列表一致。时间包含目录扫描和 `summary.json` 读取，未计入 HTTP 传输和浏览器渲染。
